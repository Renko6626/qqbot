# NoneBot 与管理页

用户已确认：一个 NoneBot 容器承载多个插件；FastAPI 驱动提供管理页面和接口，原生 HTML/CSS/JS，无前端构建系统。配置使用单个持久化 JSON，独立管理员账号密码；重启、部署和日志交给 Coolify。

## 边界

- `qqbot/app.py`：注册 OneBot v11 和管理接口，按启动配置加载插件。
- `qqbot/catalog.py`：已实现插件的元数据和配置模型，不自动扫描、导入旧插件。
- `qqbot/settings.py`：插件配置校验、JSON 持久化和群/私聊授权判断。
- `qqbot/runtime.py`：本次进程实际加载结果，供规则判断与管理页展示。
- `qqbot/admin.py`、`qqbot/static/`：管理认证、状态查询、配置保存和界面。
- `qqbot/plugins/`：各自注册 NoneBot 命令，通过公共授权规则读取当前配置，不相互导入。

底座使用 Python 3.13、NoneBot2 2.5.0、OneBot 适配器2.4.6。FastAPI + websockets 驱动同时提供管理页和主动连接 NapCat 的能力。账号密码和 OneBot 令牌从环境读取，JSON 和 API 不包含秘密。管理页使用 HTTP Basic；部署入口必须为 HTTPS。写接口要求自定义请求头，浏览器跨站表单无法提交。

全局启用、允许的群、每群用户范围、私聊用户范围和插件参数保存后作用于新消息；是否加载在下次启动时生效。宿主通过NoneBot运行前钩子统一授权，页面显示实际加载结果、错误和本次启动后的待重启变更。正在执行的处理不取消。不提供热卸载、在线 pip 安装、任意命令执行或管理 Docker 的接口。

用户后续确认方案A：管理页可请求进程正常退出，由Docker现有重启策略拉起，页面短暂检查新的启动时间。无需新增服务、Coolify token或Docker socket。镜像/环境变量更新以及故障恢复继续由Coolify管理；本地非容器运行默认不开放进程重启。

## 第一批交付

仅包含连接检查与帮助；默认不处理任何群/私聊，管理员显式开启并配置作用范围后生效。旧业务插件先保留在原目录，迁移清单见 `legacy-inventory.md`。AI、知识库和本地模型暂缓。

与 NapCat 作为同项目两个独立资源，功能容器加入 NapCat 的现有内部网络，正向 WS 接入，不公开 OneBot。管理配置挂载独立目录。首次部署为本机构建后导入 VPS；后续按用户确认改为私有 GitHub 仓库、VPS 手动 pull 和构建，再在 Coolify 点击 Restart 发布。每次构建保留提交号镜像，manual标签作为发布入口，不启用 CI。

## 界面

面向单个运维者，单页展示连接状态与插件清单。浅灰底 #f2f4f7、深蓝文字 #17233b、蓝色操作 #315bc8、绿色运行 #27745a、红色错误 #b23535。系统中文字体。插件名称、作用范围和开关为主；移动端改为纵向布局。无统计装饰、动画、外部字体或 CDN。

## 验证

用真实配置读写验证授权与重启语义；HTTP 测试验证认证、参数校验和写入结果；本地实际启动验证 NoneBot 加载。页面仅截图，不自动点击、填表或发送 QQ 消息。生产接入只读检查连接，不发送业务消息。
