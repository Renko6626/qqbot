# 大透明PNG预处理实验

2026-10-24，在开发机上比较三条图片处理路径。基线为提交`1249a31`的原型实现；本次只增加实验脚本与记录，插件默认处理路径没有变化，也没有操作VPS。

## 路径

1. `reference`：原尺寸RGBA合成白底，转RGB，再双线性缩放到384×384。
2. `paste_white`：直接创建RGB白底，用RGBA作为源和alpha蒙版执行paste，然后按原规则缩放。输入已是RGBA时省去重复转换。这条候选保持合成和缩放的顺序，减少中间图像。
3. `resize_first`：先缩小RGBA，再在384×384合成白底并转RGB。Pillow内部通过预乘alpha处理RGBA缩放，但合成/缩放顺序及整数舍入改变，不能预设输出等价。实现依据见[Pillow 12.3.0 Image.py](https://github.com/python-pillow/Pillow/blob/12.3.0/src/PIL/Image.py)。

三者均沿用EXIF方向处理、白底、BILINEAR、RGB、NCHW float32和原归一化运算顺序。实验没有引入近似阈值、置信度判断或自动切换机制。

## 测量

开发机Xeon Gold6330、Python3.13.2、Pillow12.3.0、NumPy2.5.4；模型为现有固定DeepGHS `mobilenetv3_sce_dist`，ORT1.31.0单线程。模型与配置见[原型说明](deepghs-prototype.md)。

每个方法预热2次、计时12次，每轮轮换方法执行顺序。每次计时重新打开PNG、解码、处理方向、合成/缩放及生成张量，不含推理、编码和下载。推理另用于比较最终分数。所有图片为本地生成，最大400万像素；最大的噪声PNG编码约6.6MB，低于默认下载限额。数据不代表真实群图片分布或准确率。

## 等价性与分数差异

`paste_white`在全部7个样本上，输出像素、张量和三个模型分数均与基线一致。另检查白底下全部256×256个颜色通道值/alpha组合，输出像素也逐位一致。该检查针对8位通道、白色不透明底；不把结论推广至其他底色、16位图或其他合成语义。

`resize_first`在7个样本上都出现像素差异，单通道最大差1–3。透明棋盘格中约80.4%的目标像素发生变化，模型最大概率差达到**13.784个百分点**：同一个合成样本的r18分数由99.65%变为85.87%。调色板样本最大概率差约8.26个百分点。虽然本轮最高分类均未变化，这些样本并无人工分类标签，不能据此证明近似路径的准确率，也不能只凭像素最大差很小就认定可接受。

## 结论与回退选择

推荐后续采用`paste_white`，保持先合成白底再缩放。当前样本解码加预处理降低约6%–32%，没有观察到输入或输出变化。`resize_first`保留为实验候选，不接入默认路径；出现偏差时继续使用原有合成顺序，不增加先跑近似推理再检测/重跑的流程。

噪声抠图样本的解码本身约63.8ms，paste完整处理仍约85.2ms，说明部分PNG的剩余瓶颈在解码。仅调整白底合成或迁移张量生成到Rust，无法消除PNG解码耗时。

```bash
uv run --extra nsfw python ops/experiment_transparent_png.py \
  --iterations 12 --output /tmp/transparent-png.json
```

脚本启动时验证白底颜色/alpha组合，再运行全部样本；需要已下载的固定ONNX模型。实验耗时不是QQ群端到端响应时间。原始结果见[JSON记录](benchmarks/2026-10-24-transparent-png.json)。
