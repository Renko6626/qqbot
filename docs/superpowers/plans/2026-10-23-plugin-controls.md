# 插件基础设施实施计划

用户已确认方案A：管理页内进程重启，Docker现有unless-stopped负责拉起；容器重建、环境变量和镜像更新仍由Coolify管理。不新增服务、数据库、平台令牌或Docker权限。

- 扩展现有JSON：群列表保持；每群可选用户名单；私聊可关闭、允许全部或指定用户。缺失的新字段保留旧配置行为。
- 宿主统一检查受管理插件的响应器，消息按群/用户判断，群自动事件只按群范围；不能将未知事件当私聊放行。
- 插件配置表单支持标量、枚举、简单列表；后端使用插件Pydantic模型校验。加载状态包含实际结果、加载错误和待重启变更。
- 增加受认证且校验写请求头的进程重启接口；响应后发SIGTERM，不使用Coolify token或Docker socket。页面短暂等待并检查新的进程启动时间，超时提示刷新/去Coolify，不增加后台恢复任务。
- 管理页支持按插件和按群查看权限，以及权限预览。保持单份配置，不建立第二份权限表。
- 相关已有测试加具体新行为覆盖；一次本地容器实际重启验证、页面仅截图，之后VPS备份/构建/发布并核对旧配置语义和QQ连接。

文件职责：settings.py配置与校验；runtime.py权限与加载状态；rules.py事件判断和统一钩子；lifecycle.py进程退出；admin.py管理API；static/forms.js类型表单；static/admin.js与index.html交互展示；tests/覆盖实际行为。旧业务插件不在本次迁移范围。
