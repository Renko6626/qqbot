# 公共图集与定时晚安

## 已确认的需求与路线

用户确认 Python 自带异步循环的定时方案，并提出将图集做成统一基础设施供多个插件读写。现有自动图片监测改为写入一个新图集，历史图片不迁移、不再使用；本次不操作旧归档文件。

## 模块边界

- `qqbot/albums.py`：公共文件存储，创建和列出多个图集、存图、列图、查看原图和随机读取。图集模块不依赖业务插件。
- `qqbot/album_api.py`：图集 HTTP 路由，加入现有管理端认证路由，复用 Basic 登录及写请求标头检查。
- `Runtime.albums`：提供公共 AlbumStore 实例，根目录在现有配置文件同级的 `albums/`，默认 `data/albums/`，复用现有持久化数据位置。
- 图片监测插件只负责分析和命中判断，写入配置的目标图集；默认 `anime-rating-hits`，每群可以覆盖。识别结果、来源群和消息号作为业务元数据保存。
- `scheduled_goodnight` 插件只负责定时和发送，读取配置的图集；默认 `goodnight`，避免默认发送识别插件收集的图片。

图集采用目录 + 原图 + 同名 JSON。公共字段为图片 ID、格式、时间、来源，业务元数据独立存放。不增加数据库、调度依赖、队列、去重或恢复机制。

## 公共接口

内部接口由 AlbumStore 提供：`create_album`、`list_albums`、`add_image`、`list_images`、`image_path`、`random_image`。

- `GET /api/albums`：列出图集。
- `POST /api/albums`：JSON 中传入 `id` 创建图集，重复创建返回已有图集。
- `POST /api/albums/{album}/images`：原始图片二进制请求体，单张最大 10 MiB；返回图片记录与原图地址，不新增 multipart 依赖。
- `GET /api/albums/{album}/images`：列出图片与元数据；不存在的图集返回空列表。
- `GET /api/albums/{album}/images/{image_id}`：认证后查看原图。
- 后续用户确认补充控制页图集管理；新增 `DELETE /api/albums/{album}/images/{image_id}` 删除单张原图和元数据，`DELETE /api/albums/{album}` 仅删除空图集，非空返回 409。

图集 ID 仅允许英文字母、数字、下划线和短横线，最长 64 字符。图片文件名由服务端生成。Pillow 校验实际格式，沿用识别归档支持的 JPEG、PNG、GIF、WebP、BMP、TIFF、AVIF；保留原始字节。上传自动创建目标图集，插件首次写入也自动创建。仅阅读不创建目录。

后续用户已确认在原控制页增加“图集管理”标签，沿用现有页面风格和认证，支持新建和切换图集、上传、缩略图、原图、来源和保存时间、删除单图及空图集。删除操作在页面提示确认。不增加依赖，不执行递归删除或旧数据迁移。

## 定时晚安

- 参数：每日北京时间 `HH:MM`（默认 `23:00`）、文案（默认 `晚安，做个好梦。`）、图集（默认 `goodnight`）。复用公共参数和群参数覆盖。
- 不注册消息命令，新插件默认关闭、群范围为空，不发送私聊。
- 启动后单循环每隔数秒读取最新配置，在指定分钟内每群每天尝试一次；执行前检查插件实际加载状态、开关和群范围。
- 无连接时在该分钟内等待，超时不补发；使用当前连接的 OneBot 账号，当前宿主为单账号使用。
- 当天已尝试群仅在内存保存，不加持久化；发送分钟内重启可能再次发送。
- 文案与随机一张图片一起发送；空图集或读取失败则发文字并记录日志。文字和图片都为空则跳过。发送失败只记录异常类型，不自动重试。
- 后台任务随 NoneBot 启动和停止，不创建任务管理框架。

## 验证和交付

围绕公共图集读写与认证、监测写入、定时群权限和按日发送增加少量直接测试，复用现有测试设施。已有监测用例适配新的目录与元数据结构，保持原有断言。集中运行 `.venv/bin/pytest -q` 和两份前端脚本语法检查。不启动浏览器交互测试、不发送真实 QQ 消息、不部署。
